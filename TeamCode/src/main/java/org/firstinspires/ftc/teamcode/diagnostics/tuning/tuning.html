How to tune the flywheels

The four numbers go to the Control Hub's own velocity controller (RUN_USING_ENCODER), exactly as flywheel.java runs it. Do it in this order:

  1. Direction. Open loop 0.3 on each wheel. If it spins the wrong way, tick reversed.
  2. F (feed-forward: power per ticks/s). Run the Feed-forward sweep, press Use sweep F, then FIRST start for a first P and I, and Write. With F right the wheel already sits close to target with P alone.
  3. P (push back against error). Run a step from 0 to your shooting speed. Raise P until the rise stops getting faster; back off if it overshoots or never settles.
  4. I (removes a steady offset) — only if steps settle consistently above or below target. D (damps overshoot) — usually 0 on a flywheel.
  5. Recovery. Kick (synthetic) to search, then real shots to accept. The Recovery by gain set table below lines every set you tried up side by side.

If the wheel is at full power for the whole rise, no gain makes it faster — the motor is the limit. The verdict under each step is a rule of thumb, not a measurement.

Shots and disturbances

With a wheel in VEL mode and inside its band for 0.3 s (badge armed), any drop out of the band is logged: dip depth, time to the bottom, and time until it is back in the band — the time the shooter is not ready after a shot. Kick is a synthetic disturbance (motor output cut for a few ms); it is repeatable but is not a real ball, so accept gains on real shots.

Recovery by gain set

Every shot and kick seen from this browser, grouped by the gains that were on the wheel. Lower back at speed = the next shot can fire sooner. Do not call a winner below n = 5 per set, and alternate sets (A, B, A, B…) — the battery sags as you go. Green = lowest median with n ≥ 5.

The shooting sequence

This runs the gate logic of shooter.java with the values below, fed by the shipped intake exactly as TeleOp feeds it:

  1. Wait until both wheels are within the entry band of their target.
  2. Open the gate and run the intake forward.
  3. Keep it open while it has been open less than the minimum open time, or while both wheels are still inside the wider hold band (a ball hitting the wheel dips it — the hold band stops that dip from slamming the gate on the ball).
  4. Close and go back to 1.

Not modelled: aiming and the shooting zone (the turrets stay where they are). Needs the gate's open and close positions marked on the Turrets & servos tab first.

Gate windows

Ready = wait before the gate opened. Open = how long it stayed open. Worst dip = lowest speed while open. What good looks like: every loaded piece leaves inside one window; no window closes on speed left the hold band while a ball is still in the wheels.

Zone-entry test (idle speed)

Outside the zone the wheels idle at idle speed × target. This holds both wheels there for 3 s, then steps to the targets above and times how long until each is in the entry band — the wait before the first shot after driving into the zone. Lower idle = less wear and current, longer wait.

Turrets

The turrets are positional servos, so there is no PID to tune — only the mapping from angle to servo position that turret.java uses: pos = center ± deg / (servoRange × grB / grA). Find center (turret straight ahead), check reversed (+45° must turn to the robot's left, counter-clockwise from above), then verify the ratio by pointing at ±90° and measuring. Wrong ratio → aim error grows with angle. Offset is where the turret pivot sits relative to the robot's pose center (inches, x forward, y left) — measure it with a tape.

Gate and scoopula

Both are currently 0 / 0 in shipped code (gate.openPos/closePos, scoopula.scoopPos/unscoopPos). Move the servo until it is where it belongs, then mark it.

Labelled samples → thresholds

Hold each piece where the sensor sees it during intake and capture ~40 reads. Do RED, BLUE, EMPTY (nothing in the intake) and every other thing the sensor might see (the other game piece, a piece half-in, field tiles). Vary position between captures. The suggestion maximises correct calls over all samples using the exact intake.dominant() rule.
