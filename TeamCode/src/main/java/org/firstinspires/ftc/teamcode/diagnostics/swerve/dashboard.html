Guided bring-up

1
Identify wiring & pair encoders
Turns each pod one at a time and watches all four analog channels. This resolves which spliced encoder wire belongs to which pod, and sets each servo direction so that positive power always increases the encoder reading (which the turn PID requires). Takes about 4 seconds.
Watch the robot: pods should turn one after another, in index order.
2
Measure encoder range
Spins each pod continuously for 4 seconds and records the true minimum and maximum voltage of the Axon absolute output. These become analogMinVoltage and analogMaxVoltage.
3
Set rotation convention
Only you can see which way the pod physically turned. Spin the selected pod, watch it from above, and record whether a rising encoder reading means counter-clockwise. This sets encoderReversed. Normally identical on all four pods.
4
Capture forward zero
Servos are limp whenever no routine is running, so you can turn each pod by hand. Point every wheel straight forward, all bevel gears facing the same way, then capture. This sets angleOffsetRad. Use nudge if a pod is stiff.
5
Tune the turn PIDF
Commands a step on the selected pod using the real CoaxialPod control path, so whatever you tune here transfers directly to competition code. Set kS to the measured breakaway first, then kP for speed, then kD to damp overshoot. Do not tune kF - CoaxialPod feeds the PIDF a sign, not an error, so the F term is a ±kF relay rather than a feed-forward. It ships at 0 and kS replaces it.
Values follow the selected pod and stop updating once you start typing. The pulsed row is a shelved experiment and is a no-op while unchecked.
Measures kF from stiction, then sweeps kP and kD against scored 90° steps. About 25 seconds; only the selected pod moves.
commanded heading actual encoder heading
The solid line should reach the dashed one quickly and stay there. Slow to arrive means kP or kF is too low; overshooting past it and ringing means kP is too high or kD too low.
6
Verify kinematics
Drives the whole drivetrain through a real Pedro Swerve object at low power. Forward should point all wheels forward; rotate should form the classic X pattern. Hold a button to drive, release to stop.
ON = right stick steers a heading setpoint (full stick = the robot's true max turn rate). On release it coasts to a stop, snaps the setpoint to the measured heading, and the X-lock takes the hold — the PIDF never fights the X. OFF = raw rotation.
X-lock matches competition. Hold-heading is easier to read while tuning, because X-lock yanks all four pods to the X on any momentary loss of input.
If a wheel drives backward while the others drive forward, flip that pod's drive flag on its card below.

Robot heading PIDF

heading --° target --° loop -- Pinpoint IMU
Captures the current heading as target, rotates the robot away from it with the controller off, then closes the loop and records the recovery. Starting from a genuine offset is what exposes the gain — displacing under control only shows the controller chasing itself. Needs clear space to spin.
turn by Turns by that much and holds. Small and large moves stress the loop differently — big ones saturate the output and arrive carrying momentum.
circle test Drives a circle while holding heading — needs heading hold on and clear space. Watch the graph stay flat.
